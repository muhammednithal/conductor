# Milestone 6 — Hardening, Observability, and Documentation Finalization

## Goal
Make Conductor production-ready by adding chaos testing, Prometheus metrics, OpenTelemetry distributed tracing, rate limiting, and completing all documentation.

## Scope
- Chaos testing: kill a worker mid-run and verify automatic reclaim and recovery
- Prometheus metrics per service: `conductor_{service}_{metric}_{unit}` naming; latency histograms, error counters, throughput counters
- OpenTelemetry tracing: `{service}.{operation}` span naming; `traceparent`/`tracestate` propagation; spans at all service entry points, DB calls, Redis calls, external calls
- Rate limiting: 60 req/min per workflow in api-ai; Redis token bucket (`ratelimit:workflow:{workflow_id}`)
- Final documentation review: update `docs/PROGRESS.md`; verify all ADRs and milestones are complete

## Non-Goals
- New feature development
- Breaking API changes
- Infrastructure provisioning (Terraform, Helm)

## Acceptance Criteria
1. Killing a worker process during a 5-step run causes all in-progress steps to be reclaimed and re-executed within 45 seconds with no data loss
2. Prometheus scrape endpoint (`GET /metrics`) on orchestrator returns `conductor_orchestrator_step_duration_seconds` histogram
3. A distributed trace spans from `POST /workflows/{id}/runs` in api-ai through orchestrator scheduling to worker execution
4. Exceeding 60 LLM requests per minute for a workflow returns HTTP 429 with a `Retry-After` header
5. `docs/validate.sh` exits with code 0 (zero errors, zero policy violations)
