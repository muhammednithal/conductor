# Milestone 3 — AI Step Types via FastAPI Integration

## Goal
Add the FastAPI api-ai service with JWT authentication, workflow CRUD, run triggering, and `summarize` and `embed` AI step types. Workers delegate AI steps to the api-ai service using idempotency keys.

## Scope
- FastAPI api-ai service: JWT auth (`POST /auth/register`, `POST /auth/login`), workflow CRUD, run trigger, run history
- `summarize` and `embed` step types: worker calls `POST /ai/summarize` or `POST /ai/embed` with `Idempotency-Key` header
- AI endpoint idempotency: Redis cache for 24h; `INSERT ... ON CONFLICT DO NOTHING` for step deduplication
- Token and cost tracking: `GET /ai/cost`
- Pluggable LLM provider interface (OpenAI as default provider; selectable via `LLM_PROVIDER` env var)

## Non-Goals
- RAG query step type
- Web dashboard
- SSE event streaming
- Rate limiting (deferred to M6)

## Acceptance Criteria
1. `POST /auth/login` returns a JWT token; all non-auth endpoints reject requests without a valid Bearer token with HTTP 401
2. A workflow with a `summarize` step executes end-to-end; the step's `output` in Postgres contains `{summary, tokens_used}`
3. Sending the same request twice with identical `Idempotency-Key` returns the cached result without calling the LLM
4. `GET /ai/cost` returns the total tokens and cost for completed runs
5. `make test` and `make lint` pass in `/api-ai`
