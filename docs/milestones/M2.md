# Milestone 2 — Reliable DAG Execution with Fault Tolerance

## Goal
Extend M1 to support DAG branching and fan-out, exponential backoff retries, heartbeat-based lease management, automatic lease reclaim, and crash recovery on orchestrator restart.

## Scope
- DAG branching: steps with multiple `depends_on` entries; fan-out execution
- Retry with exponential backoff: `min(base * 2^attempt, 300s) * uniform(0.8, 1.2)`; `max_attempts` per step
- Heartbeat goroutine in worker; lease renewal every 10s; lease duration 30s
- Lease reclaim background goroutine in orchestrator (scan interval 15s)
- Crash recovery: re-queue `QUEUED`/expired `RUNNING` steps from Postgres on orchestrator restart

## Non-Goals
- AI step types
- Web dashboard
- Rate limiting
- FastAPI integration

## Acceptance Criteria
1. A diamond DAG (A → B, A → C, B → D, C → D) completes with all steps in `SUCCEEDED` state
2. A step that fails twice and succeeds on attempt 3 results in a `SUCCEEDED` step with `attempt_count = 3`
3. When a worker process is killed mid-execution, its steps are reclaimed and re-queued within 45 seconds
4. After orchestrator restart, in-progress workflows resume without manual intervention
5. `make test` and `make lint` pass in both `/orchestrator` and `/worker`
